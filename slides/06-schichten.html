Beispiel / Drei Schichten, eine verbotene Richtung

BusinessLogic braucht keinen Rückweg.

Die Pfeile zeigen Typabhängigkeiten. Nicht den Weg eines Requests.

Demo: drei Namespaces in einer Assembly. So zeigt der Test die Verletzung, bevor ein Projektzyklus den Build stoppt.

API kennt BusinessLogic, BusinessLogic kennt Model. Die Rückrichtung von BusinessLogic zur API ist verboten. Der Pfeil meint eine statische Typabhängigkeit, keinen Methodenaufruf zur Laufzeit. Für die Demo liegen die drei Schichten bewusst in einer Assembly und sind über Namespaces getrennt. Würden wir zwei getrennte Projekte mit gegenseitigen Projektverweisen anlegen, könnte bereits der Build den Zyklus verhindern. Dann hätten wir einen Compilerfehler demonstriert und keinen Architekturtest. Im echten Projekt nutzen wir selbstverständlich die Grenzen, die der Compiler bereits durchsetzt. Der Test schützt dort zusätzliche Entscheidungen, die ein technisch zulässiger öffentlicher Typ allein noch nicht absichert.
