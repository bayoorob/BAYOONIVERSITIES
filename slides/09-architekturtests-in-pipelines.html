  • Wie andere Tests ausführen, im Pull Request verpflichtend machen.
  • Regeln und Anwendungscode gemeinsam versionieren.
Architekturtests auszuführen braucht keine besondere Infrastruktur. Sie laufen mit `dotnet test` und lassen sich direkt in unsere bestehende Pipeline aufnehmen. Idealerweise machen wir sie über die Branch Policies verpflichtend. Ein Architekturverstoß blockiert dann den Merge. Die Regeln liegen im selben Repository wie unser Anwendungscode. Damit werden Architekturänderungen genauso versioniert und im Code Review geprüft wie jede andere Änderung auch.
