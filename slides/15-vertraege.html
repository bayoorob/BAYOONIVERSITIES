Vertiefung / Öffentliche Verträge

public ist keine Architekturfreigabe. 


namespace Shop.Customers.Contracts;

public sealed record CustomerSummary(Guid Id, string Name);

public interface ICustomerLookup
{
    CustomerSummary Find(Guid customerId);
}

Orders kennt den Vertrag, nicht die Kundenpersistenz.

C#-Ausschnitt einer Contracts-Assembly · System für Guid importieren

Eine Modulgrenze braucht nicht automatisch ein neues Interface für jede Klasse. Hier ist der Vertrag sinnvoll, weil das Bestellmodul genau eine Kundeninformation benötigt, ohne die konkrete Speicherung zu kennen. CustomerSummary gibt weder einen DbContext noch eine EF-Entity nach außen. Die Implementierung von ICustomerLookup darf intern EF Core verwenden; Orders muss das nicht wissen. Ob der Port im konsumierenden Modul oder in einer freigegebenen Contracts-Assembly liegt, ist eine Architekturentscheidung. Das Interface allein erzwingt sie nicht. Für interne Typen ist internal die stärkere Grenze, soweit wir sie nicht bewusst über InternalsVisibleTo öffnen. Für öffentliche Implementierungen kann eine zusätzliche Abhängigkeitsregel helfen.
